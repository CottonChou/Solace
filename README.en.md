# Solace

**One sentence, a finished task, on your own phone.**

Solace is an Android personal assistant that runs on your phone: it operates apps and websites in the background while your screen stays yours. Bring your own model API key — there is no cloud service, and your data stays on the device.

## What it can do

Solace adapts by understanding the screen, not by integrating app by app. It works like a capable person sitting next to you: reads the interface, understands the content, taps and types until the task is done.

| Capability | What it means |
|---|---|
| **App control** | Opens any installed app on a separate background screen and reads, taps, types and scrolls there. Long chats and lists are read screen by screen. Apps with unreadable controls fall back to bundled text recognition; a vision-capable model adds screenshot grounding. |
| **Web control** | Opens sites in desktop mode in the built-in browser, with real clicks and keyboard input. Logins persist, downloads and uploads work, visits are paced, and anti-bot pages are handed back to you instead of forced through. |
| **Current screen** | A floating capsule stays at the screen edge. Double-tap it to send what you are looking at to Solace — "how should I reply to this", "note this down". |
| **Scheduled tasks** | One-off reminders, recurring jobs and conditional tasks such as "check the weather every morning and tell me only if it will rain". Results return to the original conversation. |
| **Memory** | Remembers facts, preferences and approved ways of working. You can view, edit and delete everything; passwords, verification codes and card numbers are never stored. |
| **Linux sandbox** | Each conversation gets a workspace for Python, Node and shell. Offline by default. arm64 devices only. |
| **Real takeover** | Login, verification codes and payment pause the task and hand control to you. After you hand back, Solace re-checks the screen before continuing. |

## Safety

Automation touches your real accounts and real data, so these rules are designed in, not bolted on:

- **Banking and payments are hard-denied.** Banking, brokerage and payment apps are rejected at the engine layer, with no unlock switch.
- **Every messaging write is confirmed.** Sending or modifying content in WeChat, WhatsApp and similar apps requires your confirmation each time.
- **System settings are read-only by default.** System packages can be observed but not changed; task-scoped grants expire when the task ends.
- **You always pay yourself.** Payment-detected actions hand control back to you; Solace never completes a purchase.
- **Lock screens show no task content.** Task notifications on the lock screen use a fixed title only.
- **Sensitive data never enters memory.** Verification codes, card numbers and IDs are filtered out before storage.
- **Crashes stop retry loops.** Repeated engine failures enter a safe mode that keeps the last known good configuration and waits for you.

## Get started

### Requirements

- Installs on Android 11+; running tasks needs Android 13+, with Android 14+ recommended.
- The Linux sandbox needs an arm64 device.
- An API key for a tool-calling model; local and LAN models also work.

### Steps

1. Install the APK from [Releases](https://github.com/CottonChou/Solace/releases/latest).
2. Add a model provider in the first-run wizard.

- "Open a job site, filter suitable roles and greet recruiters"
- "Check the weather at 8 every morning and tell me only if it will rain"

## Data and privacy

- **No Solace server.** Chats, screen data and screenshots go only to the model provider you configure.
- **Encrypted on device.** API keys, memory and user profile are encrypted with the Android Keystore; conversations and run records stay local.
- **Update checks contact GitHub Releases only**, and collect nothing.
- **The sandbox is offline by default**; the built-in browser visits only sites you send it to.

## Disclaimer

Automating third-party apps and websites may violate their terms and carries account-restriction risk. Use your own judgment. For money, accounts and important messages, prefer confirmation mode and check the result.

## FAQ

**Is retrying after a failure risky?**

Solace records why each attempt failed and enters a safe mode after repeated anomalies, instead of repeating the same risky action forever.

**Why was a system-settings action denied?**

System packages are read-only under the built-in policy. If a task genuinely needs to change system state, approve it for that task; the grant does not survive into later tasks.

**The app moved to my main screen. Is that normal?**

That is takeover. Login, verification codes and payment belong to you; hand back when done and Solace verifies the current page before continuing.

**Tasks keep getting killed on ColorOS.**

Open the three OPPO / ColorOS keep-alive entries on the system-capabilities page: battery and background running, auto-start, and background pop-up. These are vendor pages Solace cannot operate for you; turn them on manually.

**Can I use a LAN model?**

Yes. Add a custom provider with a LAN address. Unencrypted addresses show a warning; prefer HTTPS when available.

**What happens when I change phones?**

Conversations, memory and API keys live on the device, encrypted, and are deliberately excluded from cloud backup; set the new phone up from scratch. This is part of the privacy design.

## For developers

```bash
./gradlew :app:assembleDebug                  # debug build
./gradlew :app:assemblePerf                   # precompiled like release, debug-signed
./gradlew :core:test :app:testDebugUnitTest   # unit tests
```

The debug build is not precompiled and its UI is noticeably slower; do not judge smoothness with it. Architecture notes live in [`docs/architecture.md`](docs/architecture.md); roadmap and known issues in [`docs/roadmap.md`](docs/roadmap.md).
